Trusted lineage: the server automatically selects the current verified production predecessor, binds the new immutable snapshot to its predecessor release and snapshot hash, and creates the lineage hash. Predecessor IDs and hashes cannot be supplied by the browser.

Release attestation: after trusted construction, an administrator-created server attestation binds the release ID, model version, snapshot hash, predecessor hash, lineage hash, construction timestamp, and authorized creator identity. Promotion and runtime activation require a valid attestation.
